amusemonk = Next.js port of `~/Desktop/noel/file-to-api-payout` (Express/EJS/Postgres), started 2026-10-29. Repo `~/Desktop/noel/amusemonk` (noel identity). Domain amusemonk.com. Plan in repo `PLAN.md`, design rules in `CONTEXT.md`.

Decided by the user 2026-10-29:
- Auth = NextAuth Credentials against Celestia sandbox gatekeeper `https://sandbox.celestiapayment.com/api/v3/gatekeeper/identity/sessions` (cekko pattern, `~/Desktop/noel/cekko/src/auth*.ts`).
- Payouts = UAPI `/uapi/v1/peatio/account/{balances,payouts/initiate,payouts/status}`, signed with the **logged-in user's own** key. Secret is shown only at creation (`POST /api/v3/gatekeeper/resource/api_keys` + otp_code, see `~/Desktop/noel/atlas/app/api/api/v3/resource/api_keys.rb`), so the app creates and stores it encrypted.
- Idempotency key = file's `client_reference_id`, verbatim, no `-R2` retry suffix.
- No gateway-settings UI ("backend's job").
- Upload rules configurable in DB; duplicate-id + fingerprint rules locked on.
- RDS MySQL, S3, single EC2 + Docker Compose (web + worker + Caddy). AWS key = `~/dev-notes/_private/aws-henry-ws.env` (account …9028); `~/.aws` default key is invalid. Region: first `eu-west-2` London (user, 2026-10-29), now **`us-east-1`** (D-47, below). A first build in `ap-south-1` was my unasked pick and was torn down (rule: always ask the region, global CLAUDE.md).
- UI: corona (`~/Desktop/noel/corona`) is a structural reference only — must NOT look identical (client must not link the two products). Own palette, names, copy.

**Why:** client-facing product; the corona-likeness constraint is a confidentiality requirement, not taste.
**How to apply:** never copy corona's theme names, palettes, logo or copy; reuse only architecture.

**VPN egress (user rule, 2026-10-29):** every call to outside/backend APIs goes through the VPN. gluetun with `~/Desktop/noel/relay/_private/proton/darwin.env` (copied to git-ignored `amusemonk/credentials/darwin.env`), HTTP proxy :8888 → `EGRESS_PROXY_URL`; only `src/lib/egress.ts` `outboundFetch` may call out (ESLint bans bare `fetch`). Consequence: rotating exit IP → can't IP-whitelist per-user UAPI keys (open question).

**Desktop-first (user, 2026-10-29):** desktop is the main use case. Design and verify screens at desktop width first (dense tables, wide layouts are fine); mobile only needs to not break.

**Admin (user, 2026-10-29):** admin panel `/admin` = gatekeeper role `super_admin` only (atlas `User#super_admin?`). Manages upload_rules (global, one set), users' user_api_keys, other config. No local app_role column.

**UAPI keys (Step 5, 2026-10-29):** created with `scope: "uapi"`, `whitelisted_ips: ["*"]` — gatekeeper treats an EMPTY whitelist as deny-all. Atlas bug: `PATCH /api/v3/gatekeeper/admin/api_keys/:id` looks up `declared_params[:kid]` (nil) → always 404, so admin revoke in amusemonk is local-only (CONTEXT D-24). Not yet reported to atlas owners.

**Step 6 (2026-10-29):** rules engine + ingest + storage done. Gotchas: exceljs must NOT be in `serverExternalPackages` (nested `generator-function` .mjs breaks Next's require); `next.config.ts` can't import files using the `@/` alias (hence `src/lib/limits.ts`); local storage needs `/* turbopackIgnore: true */ process.cwd()` or standalone output traces the whole repo. S3/RDS go direct, not via VPN (user confirmed, D-28).

**Step 7 (2026-10-29):** workers done (`src/worker/`). Approval = uploader approves own file only (user decision, D-29; the user said "its user file, he will approve"). Test harness (fake UAPI gateway + 17 worker scenarios) lives in the session scratchpad, to move into the Step 9 suite.
