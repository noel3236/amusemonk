How it works

From spreadsheet to settled in four steps

No integration to build. If you can export a spreadsheet, you can send a batch.

  1. 1

    Upload the file

    CSV or Excel, one row per payout: reference, account, bank code, amount, date and beneficiary.

  2. 2

    Every row is checked

    Columns, formats, limits, dates and duplicates. If one row fails, the whole file is held back and each problem is listed by row.

  3. 3

    Review, then confirm

    See every payout and the total before anything is sent. One confirmation sends the batch.

  4. 4

    Track until settled

    Each payout moves from processing to paid on its own. If the bank returns one, you see why.

Safeguards

Built so a payout can't go out twice

All or nothing

A file is accepted whole or not at all, so a batch never half-sends. Fix the rows that are listed and upload it again.

Exactly once per reference

Every row is keyed by your own reference. The same file uploaded twice, or the same payment under a new reference, is stopped before it's sent.

Rules you set

Limits per payout and per file, date windows and allowed accounts. Change them without touching the file format.

Status you can trust

Each payout is followed until it settles. If a response is lost, the payout is looked up, never sent again blind.
